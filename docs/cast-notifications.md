# 投放中的紧凑通知

虚拟投放期间，符合通知总开关、应用选择、勿扰和倒扣条件的通知，会显示为摄像头安全区顶部的紧凑胶囊。图标、标题和一行摘要覆盖在原投放画面上，不缩小或移动画面，不启动通知 Activity，也不暂停投放或切换背屏任务。

胶囊按已有的“通知显示时长”自动消失，无障碍建议时长可能延长显示。连续通知直接替换当前内容并重新计时，不排队展示已经过期的消息。长文字在行尾截断；标题、正文的隐私设置和通知暗夜模式继续生效，常规模式跟随系统深浅色。

点按胶囊会立即关闭，不跳转或展开。胶囊范围内从按下到抬起的完整手势由通知消费，不会点击到下方 App；区域外继续沿用投放触摸路径。拖动或多指不会误关闭通知，通知到期或替换也不会把仍按住的手指转成 App 点击。打开投放菜单、切换显示范围、暂停或关闭屏幕时，胶囊隐藏；恢复可见时，只显示仍未过期的最新通知。结束投放后清除内容和定时任务。

没有虚拟投放宿主时，继续使用原全屏通知流程。物理直投保持原显示流程。虚拟投放期间插电改用同一胶囊，显示充电状态和当前电量，8秒自动消失或点按关闭；充电常亮开关不会让胶囊长期覆盖投放。重复同一次插电不会重新弹出，拔线仅清理仍显示的充电提示。消息与充电胶囊按最新事件替换，拔线不关闭后来的消息。没有投放宿主时，充电仍使用原来的全屏/常亮动画。

## 实现边界

- `RearCastNotification` 在进程内将消息交给当前宿主，旧宿主销毁不会注销新宿主。原通知监听服务先完成筛选和隐私处理，再尝试宿主投递；充电服务在领取全屏会话之前尝试投放内提示，待连接期间也重新判断宿主。
- `RearCastNotificationOverlay` 是宿主内的 View，复用主题颜色；没有新增窗口、服务、权限或持续刷新循环。显示前通过当前投放会话向输入代理注册物理点击范围，成功后才显示。注册失败则隐藏胶囊，保留投放。
- `VirtualRearHostActivity` 在当前物理安全区定位胶囊，内容旋转与全屏/避让切换不会改变通知的物理安全区。
- 此路径不领取 `RearAnimationManager` 会话，不暂停 Keeper，仅通过限定接口登记当前会话的点击区域，也不执行“恢复官方桌面”；因此不会触发此前发现的通知结束误停虚拟投放链路。

## 验证

主机检查：`python3 tools/test_cast_notification.py`，覆盖宿主交接、过期、内容边界及旧宿主注销隔离。

Android 检查：`RearCastNotificationTest`，覆盖服务分流、连续通知续期、隐藏期间过期、关闭清理、点按关闭与触摸区域注册确认以及安全区、深浅色、大字号和系统动画关闭。测试使用隔离模拟器与专用副屏夹具；不等同于小米真机硬件链路验收。

触摸隔离检查：`python3 tools/test_cast_notification_touch.py`，覆盖区域外原触摸、区域内点击、拖动、多指、过期/换代期间按住、取消与显示恢复。

小米17 Pro Max正式包真机预览已确认：自动消失期间保留原投放任务；点按可关闭胶囊，计算器继续显示。测试通知和临时偏好在验收后恢复。此结论不代表其他型号或物理直投已验收。

充电胶囊也已通过小米17 Pro Max正式包系统电源广播链路验证：插电显示充电/满电状态与电量，8秒后消失，拔线清理提示；期间投放宿主和计算器任务保持不变。真实电源上报及原设置已在测试后恢复。
