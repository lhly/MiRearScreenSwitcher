# 背屏显示方向修复验收（2026-10-16）

## 原因与行为

原实现仅执行 `wm user-rotation -d 1 lock N`，以退出码判断成功，并将锁定请求当成当前方向。真机曾出现请求为180°、实际仍为0°的状态：背屏默认不固定用户方向，官方Launcher的竖屏请求覆盖了用户设置。

现在设置背屏方向时，先启用 `fixed-to-user-rotation`，再锁定角度，回读策略和请求，并在有限次数内核对 `dumpsys window displays` 的实际 `mRotation`。失败时恢复原来的free/lock及固定方向策略。主屏不启用背屏专用策略。

实际角度按显示器区块解析，忽略配置中的同名字段和 `mUserRotation`。读取失败返回-1；首页显示“—”，不默认选中0°。回到页面时重新读取，设置失败后也会刷新实际状态。Shizuku远端实现版本递增至2，升级后重新加载实现。

90°充电联测发现旧安全区域缓存仍位于自然方向的左侧，导致电量文字被挤成两行。充电页改用当前窗口Cutout Insets，随方向更新并清除旧边距，电量保持单行并在支持的系统上自动调整字号。

## 真机验证

设备为小米2509FPN0BC，Android 17 / SDK37，HyperOS OS4.0.0.44.XPBCNXM。同签名覆盖安装，保留原设置与数据。

- 从原生首页实际点击90°、180°、270°、0°，每次都唤醒背屏，确认系统实际角度分别为1、2、3、0，固定用户方向已启用，按钮checked与角度一致。主屏始终为lock0。
- `mrss://config?rotation=1` 通过相同后端生效。强制停止并重开应用、重新连接服务后，实际90°保留，首页回读90°。
- 在90°下模拟接通电源，普通充电模式于1.090、4.089、7.805秒均在背屏前台，实际角度保持1；8秒后执行退场，退出日志间隔279ms（含调度），恢复官方Launcher且仍为90°。
- 目视复核596×976截图，80%完整单行，位于当前安全区域中央。
- 最终安装APK与构建产物SHA256一致，原应用 `ceDataInode=4688717` 保留。

测试结束恢复原背屏策略default、请求lock2，亮屏复核实际0；主屏lock0保持。电池模拟已reset，AC/USB/Wireless/Dock四项电源来源与原状态一致，原前台Bilibili任务已恢复。专用模拟器5558在回归后关闭。

验收覆盖当前连接手机和专用模拟器；未执行整机重启或逐个第三方应用、通知布局的真机兼容测试。
