# 背屏能力识别与兼容性测试

背屏操作共用运行时识别结果，不以机型字符串或固定显示编号判断支持。不同设备与系统版本的适配效果需结合实际环境验证。

## 识别与失败处理

- 从系统显示清单选取唯一的非主屏内置物理面板，排除外接屏和虚拟屏。多个内置候选时，只接受唯一的背屏语义标识；无法确认时终止操作并记录原因。授权服务向界面进程同步编号与唯一标识，显示变化后重新读取。
- 普通投放、通知、充电、DPI、旋转、唤醒及截图使用相同的背屏编号。截图与录屏的物理显示地址来自选中的面板，不按 SurfaceFlinger 清单顺序猜测。
- 任务迁移先找到目标任务所属的 root task，再调用当前系统的 `moveRootTaskToDisplay`；接口不可用时尝试系统的 `am display move-stack`。两条路径均复核实际任务位置，不固定 Binder transaction 编号。
- 虚拟投放先读取触摸设备能力，结合系统显示关联、既有设备身份、背屏语义名称与主背屏几何差异选择唯一候选。几何回退仅用于系统明确标识为内部设备的直接触摸屏；拒绝主屏、外接触摸、触摸板和多候选歧义。读取器在接管前再次核对完整设备名、坐标范围与触点数量，保留释放、超时、父进程退出与租约回收。
- 有效显示信息明确返回无 cutout 时可使用整个报告区域；已有 cutout 则继续采用系统安全边距。字段缺失、读取失败、无效尺寸或不符合既有旋转条件时仍拒绝启动。不会为未知相机遮挡猜测固定边界。
- 官方桌面恢复优先读取已安装系统包中的可用背屏桌面组件，并对命令回退候选进行解析确认。启动错误不会再直接返回成功。

停止投放的状态在资源恢复完成后才返回；旧投放退出时不覆盖新进入背屏的任务。启动新投放在等待旧投放清理后重新核对宿主与 Surface，防止超时后立即重试使用失效画面。

正式版的直接/虚拟投放默认值、偏好键、触摸坐标映射、四向旋转、截图手机壳资源范围和临时冻结保护保持原有约定。运行中的虚拟会话固定物理面板身份，身份变化时退出，避免切换到其他显示器。

磁贴通过系统 `startActivityAndCollapse` 启动既有透明 URI 接收器，再进入串行命令服务。Android 14 及以上使用不可变的 Activity `PendingIntent`，旧系统使用对应的 `Intent` 重载。这样磁贴与 URI 共用可见启动入口，不再只从磁贴直接启动后台服务。实现依据见 [Android TileService 接口](https://developer.android.com/reference/android/service/quicksettings/TileService#startActivityAndCollapse(android.app.PendingIntent))。

## 诊断报告

在“关于 → 诊断信息”或首页“连接详情”中收集，可复制 JSON 或通过系统分享面板导出文件。诊断收集在后台运行，未连接 Shizuku 时仍能导出基础信息；弹窗在 Activity 重建后保留。

报告包含应用、机型、Android/系统增量版本、Shizuku 连接和权限状态、显示候选与选中原因、cutout、输入能力、可用桌面组件、当前会话及限长的近期兼容性事件。它不读取通知内容，不导出通用 logcat，也不自动上传。分享由用户选择目标。

## 正式版本与反馈

v3.6.1 / 2020 合并了 compat.1、compat.2、compat.3 的累计修复，沿用正式包名与签名，可覆盖 v3.6.0 并保留数据和偏好。直接/虚拟投放以及单应用密度兼容开关不会自动改变。

王者荣耀等应用可能因切屏配置变化触发重建并退出；测试中开启虚拟投放及该应用的密度兼容后，完成登录页投放、返回和任务保留验证，未测试登录或对局。磁贴启动超时与应用因密度变化退出是不同问题，需按具体表现排查。

建议反馈以下结果：

1. 解锁状态下直接投放、返回主屏及恢复官方桌面。
2. 开启虚拟投放后的应用启动、点击、滑动、多点触摸与返回手势。
3. 四向旋转、DPI、摄像头避让、主屏锁定与重新唤醒。
4. 背屏截图/录屏、充电动画和通知显示。
5. 失败后立即分享诊断报告，并说明准确机型、触发步骤及普通/虚拟投放方式。

## 验证边界

主机回归覆盖已保存的小米 17 Pro Max 两面板数据、原始触摸范围与安全区，以及新显示编号、驱动改名、外接屏、无 cutout、元数据缺失和识别歧义。模拟器用于验证安装、界面、诊断导出及混淆后的 Binder 契约；它不能替代真机验证。

2026-11-01 在小米 17 Pro Max（2509FPN0BC / OS4.0.5.0.XPBCNXM / Android 17）通过无线调试补充验证：

- 已签名 compat.1 覆盖 APK 的实际 TaskService 正确识别物理背屏与触摸设备，完成固定横屏、不可调整大小任务的物理背屏往返及位置复核。
- 同一生产源码的独立调试包完成 200/240 DPI、四向旋转、摄像头避让/全屏的实际窗口尺寸与点击坐标检查，并验证显式 DPI 参数及保存的旋转选择。
- 已在主屏启动的固定横屏任务，分别在密度兼容开/关与摄像头避让/全屏四组配置中完成虚拟投放、点击与返回；原始 evdev 事件另经真实 native 读取器、坐标路由和应用接收验证。
- compat.2 真机验证四向旋转与安全/全屏的点击、双击、滑动和双指事件；正常停止、输出重连超时后立即重试、无效 Surface、切换中停止都正确释放输入和虚拟屏并恢复任务。已签名 APK 的真实 Binder 截图接口返回 976×596 PNG。

配置变更可能触发目标应用重建或主动退出；任务位置复核通过不代表目标应用的画面和进程完整可用。对于此类应用，需要分别验证普通投放、虚拟投放和单应用密度兼容，不能统一改变所有小米 17 用户的默认方式。

上述结果只覆盖该台设备和系统版本；其他设备与系统版本、充电/通知完整生命周期、功耗和长期稳定性仍需对应环境验证。

compat.3 在同一台 17 Pro Max 上补充实际系统磁贴检查：固定横屏目标的虚拟启动、返回和任务保留通过；主屏进入息屏显示的非交互状态时，背屏会话保持运行。独立于控制器的设置页面完成普通/虚拟投放与返回，普通投放没有创建虚拟显示或接管输入。19 项连接与路由回归覆盖新旧系统的磁贴启动 API；release 和 compatibility 构建与 lint 通过。未延长启动超时，未加入常驻亮屏标志，也未更改用户的单应用密度默认值。
