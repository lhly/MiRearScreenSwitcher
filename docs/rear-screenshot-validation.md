# 带壳背屏截图

## 行为

在“背屏 → 背屏截图”开启“添加手机外壳”，可选完整机身、局部放大和当前机型对应的官方外观，并可同时保存原图。默认保持原始截图。磁贴与 `mrss://screenshot` 使用同一配置与保存流程；图片保存在 `Pictures/RearDisplay`。

模板按 `Build.DEVICE` 自动匹配，无需手动选机型：

| 机型 | 代号 | 官方外观 |
| --- | --- | --- |
| Xiaomi 17 Pro | `pandora` | 黑、白、紫、绿 |
| Xiaomi 17 Pro Max | `popsicle` | 黑、白、紫、绿 |
| Xiaomi 18 Pro | `hongkong` | 黑、白、粉、深蓝、红、红色透明外观 |
| Xiaomi 18 Pro Max | `madrid` | 黑、白、粉、深蓝、红、红色透明外观 |

共20套官方资源，每套均包含完整和局部构图。配色名称按实际素材外观描述；不同配色的机身画布尺寸可能不同，始终读取该资源自己的 JSON 参数。恢复旧设置后，若保存的配色不属于本机可用列表，本次预览和截图均使用黑色，不改写原保存值；未知机型保持外壳开关不可用，仍可截图。

首次使用联网获取，验证官方 SHA1 后安装到应用私有缓存；PNG、JSON 不打入 APK。网络、模板、比例或合成失败时保存原图并明确提示，不再无条件报告截图成功。

## 实现边界

- Shell 服务按物理背屏地址捕获，PNG 通过文件描述符传回应用，同时返回方向与尺寸，避免按 SurfaceFlinger 输出顺序误取主屏。
- 应用按 JSON 的屏幕区域和四边距合成，保留透明区域、摄像头及机身构图；物理旋转先映射回模板坐标，虚拟投放中的内容旋转仍由实际画面呈现。
- Android 10 及以上使用应用自有 MediaStore 条目，写完才发布，失败清除未完成条目。Android 7 至 9 保留 shell 文件描述符保存入口。
- 新 AIDL 事务使用 37、38，原事务编号保留；Shizuku UserService 版本递增以更新已有进程。
- 磁贴忽略 500ms 内的重复点击回调；已解锁时直接执行，锁屏解锁回调每次只消费一次，避免多显示屏系统重复分发造成重复图片。
- 设置页和调试预览夹具共用 Miuix 页面。夹具仅指定预览模板，不模拟背屏捕获，且不进入 release。
