# 背屏充电动画修复验收

日期：2026-10-16。基于 ReMRSS 3.3.3 / 2015，本地修复，未改版本号、推送或发布。

## 原因与修复

原流程先在主屏创建透明占位页，再移动到背屏。`RearScreenChargingActivity.onCreate()` 在主屏直接返回，未创建布局或注册退出接收器；迁移后没有补初始化。真机原页面在 display1 存活，但 content 容器为空。`singleInstance` 后续复用此空页，又没有处理新 Intent。

修复内容：

- 充电服务直接在 display1 启动，并验证任务的实际显示屏；shell、显示信息读取及唤醒操作移到后台队列。
- 页面在创建、恢复、配置变化和窗口挂载时检查是否需要初始化；处理新 Intent，刷新电量并重新安排普通模式的 8 秒计时。
- 占位阶段也注册拔线/通知打断接收器；销毁时取消计时、动画并清除实例引用。相同电量更新不打断最初的液体填充动画。
- 等待 Shizuku 连接最多 5 秒；拔线或停止服务会取消请求。结束广播携带请求 ID，旧页面退出不能关闭快速重插后的新动画。
- 恢复原投放任务或通过统一接口启动官方背屏 Launcher，再恢复 Keeper 监控；恢复操作与新启动串行执行。

签名正式包已同签名覆盖安装到连接手机，保留原应用数据。通过 `cmd battery` 临时模拟电源连接/断开，执行真实系统广播 → ChargingService → Shizuku → 背屏页面链路，确认：

1. 插电事件后出现绿色液体动画和电量，实际背屏截图为 69%。
2. 断电事件后充电 Activity 销毁，官方 Launcher 恢复。
3. 短间隔再次接电能重新显示动画。

电池模拟在 `finally` 中通过 `cmd battery reset` 恢复，四项电源来源与测试前一致，没有残留冻结状态。独立调试包及测试包已卸载，项目专用模拟器已关闭。未主动锁屏/解锁，也未代替用户操作实际数据线；硬件插拔和锁屏下的最终观感仍可由用户日常使用复核。

## 普通模式与退场追加修复

用户实测发现关闭充电常亮后约1秒消失。真机事件确认：页面在20:33:58.533就绪，系统在20:33:59.711把官方Launcher移到前台，8秒计时尚未到期。上一轮普通模式的真机持续可见性验收不完整，已补充以下处理和验证。

- 普通模式和常亮模式播放期间均维持背屏显示；常亮开关仅决定是否自动结束。普通模式保持8秒，再以250ms透明度动画淡出，使用ease-out曲线(0.23, 1, 0.32, 1)。
- 自动退出和拔线退出均有退场；通知打断立即交接，系统关闭动画时直接完成；新Intent取消旧退场，防止旧结束回调关闭新动画。
- 新增普通模式短时保亮、关闭常亮后继续保亮、淡出中间帧、退场中重启和系统关闭动画五项回归。18项充电与8项首页共26项通过（52.924秒），共享连接16项通过；构建和Lint通过。
- 最新签名包已覆盖安装到真机，使用系统电池模拟触发普通模式：1.049、2.541、5.045、7.749秒均保持背屏前台，8秒后开始退场。日志中退场实际耗时约276ms（含帧调度），背屏截图已观察到全亮72%到逐渐变暗的中间帧，随后恢复官方Launcher。
- 电池模拟已恢复；本轮没有修改手机系统动画倍率，关于关闭动画的回归在专用模拟器执行。
