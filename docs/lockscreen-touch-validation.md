# 主屏锁定后的背屏触摸修复

2026-10-30，在 2509FPN0BC / HyperOS OS4.0.4.0.XPBCNXM 上验证；测试对象为 Anx Reader 1.14.0。正式签名修复包沿用 ReMRSS 3.5.0 / 2018，控制服务实现版本28。

## 原因与方案

原故障中，HyperOS Greezer 在主屏熄灭后冻结了虚拟背屏中的阅读器。冻结记录先于输入响应超时5秒；旋转触发显示变化时短暂解冻，随后再次冻结。直接注入虚拟显示的系统点击同样受阻，说明问题涉及系统冻结，而非仅触摸坐标转换。ReMRSS 菜单由独立进程处理，因此仍可打开。

修复在虚拟投放期间临时维护冻结服务读取的 `Settings.System.MILLET_NO_RESTRICT_APP` 镜像，只添加当前投放包，不修改 PowerKeeper 中的用户电池策略，也不全局关闭冻结。结束时撤销本次添加的条目，原本已在名单中的应用保持原样。

独立 shell 守护进程持有恢复文件锁，设置写入前记录原值；管道关闭或6秒租约失联后执行恢复。名单未发生其他变化时精确恢复原字符串，否则仅撤销本次条目、保留其他包的新变化。系统重建镜像时重新合并当前包。守护进程意外退出由会话发现后补偿；残留恢复记录在下次控制服务连接时处理。

## 验收结果

| 检查 | 结果 |
| --- | --- |
| 主屏锁定且电源状态为 Dozing，连续24次系统点击 | 六次状态快照中目标均未冻结，输入连接保持响应，应用状态检查成功 |
| 真实背屏连续点击、侧滑、旋转后触摸 | 用户确认均正常 |
| 锁屏下正常结束投放 | 白名单完整原值恢复，守护和读取器退出，任务回主屏，主屏保持锁定 |
| 锁屏下强杀控制服务 | 约3秒后原值恢复，守护和读取器退出，官方背屏恢复 |
| 正式压缩 APK 守护入口的正常关闭、失联超时、守护强杀后的记录补偿、并发所有权 | 四项通过，最终原值一致、恢复记录清除 |
| 空原值、原有保护、名单并发变化、系统重建、写入/恢复失败、残留记录与文件锁 | 12项主机回归通过 |
| 既有触摸路由、坐标映射、四向旋转及范围切换回归 | 通过 |
| 正式构建、R8入口与Binder契约、签名、私有规划检查 | 通过 |

测试过程中阅读器进程保持不变，未清除阅读数据；最终结束测试投放，撤销临时保护并恢复官方背屏。软件注入检查不替代真实手势，真实手势结论来自用户确认。

## 边界

- 控制服务与守护进程同时被强杀时，不能保证即时恢复；下次控制服务连接会补偿残留记录。PowerKeeper 自身也会按真实用户策略重建镜像。
- 此次验证覆盖当前 ROM 的常规锁屏场景，其他 ROM、极端省电或系统冻结策略变化须重新验证。
- 本次修复针对虚拟投放；锁屏后启动新的投放仍可能受系统限制，需要手动解锁。修复不会解除主屏锁定。
