# ReMRSS 使用指南

本指南按当前 ReMRSS 界面整理。各版本的功能以对应 [Release](https://github.com/lhly/MiRearScreenSwitcher/releases) 说明为准；可在“背屏”页打开离线“使用教程”，点击章节展开步骤，末尾“教程来源”保留腾讯原图文教程入口。

## 初次设置

1. 在支持背屏的小米设备上安装 ReMRSS。
2. 选择权限来源：默认使用 [Shizuku](https://shizuku.rikka.app/)，按其引导启动服务；已 root 的手机也可直接使用 Root 模式。
3. 打开 ReMRSS。使用 Shizuku 时完成对应授权；使用 Root 时，在首页连接状态卡选择“权限来源 → Root”，点击“授权并连接”，并在 root 管理器中允许当前安装的 ReMRSS。等待控制服务就绪。
4. 按需开启通知、充电动画等功能，再添加控制中心磁贴。

从旧 MRSS 迁移时，新包 `top.zainzh.rearscreen` 会独立安装，不会自动读取旧应用的配置和权限；需要重新配置、授权并添加磁贴。详见[迁移说明](remrss-identity-validation.md)。

## 控制中心磁贴

当前权限来源的控制服务已就绪时，可在“使用教程 → 添加磁贴与投放”点击三个添加按钮直接添加，无需选择磁贴尺寸；已存在的磁贴会提示无需重复添加。也可下拉控制中心，进入快捷开关编辑，手动添加以下三项：

| 磁贴 | 用途 |
| --- | --- |
| 切换至背屏 | 将主屏当前应用投放到背屏 |
| 获取背屏截图 | 截取背屏画面并保存到相册 |
| 背屏录屏 | 打开或关闭录屏悬浮控制台 |

### 投放与返回

1. 在主屏打开要投放的应用。
2. 下拉控制中心，点击“切换至背屏”。
3. 操作开始后控制中心自动收起，翻转手机查看背屏。

若磁贴显示“正在连接服务...”，请保持控制中心展开，连接等待最多 5 秒；提前收起可能取消请求。控制服务未就绪时，先打开 ReMRSS 检查当前权限来源；Root 的首次授权在应用内完成，不由磁贴反复发起。

要移回主屏，点击应用正在背屏运行的通知。启用接近传感器后，也可按“背屏”页的遮盖检测说明操作。

### 虚拟背屏投放

在“背屏 → 虚拟背屏投放”开启后，磁贴和 URI 自动化都会使用虚拟方式；首次仍默认使用原直接投放。虚拟方式支持右侧滑动返回、二段侧滑菜单、摄像头避让和按 App 记忆旋转及显示范围。遇到正文只显示一部分等缩放异常时，可在“密度兼容”列表为该 App 开启兼容；所有 App 默认关闭。

“密度兼容”只在虚拟模式下显示，已开启的 App 分组置顶。可为已开启应用设置72–640的布局 DPI，默认200；数值越小，可显示的信息越多。全部关闭兼容时仍使用虚拟投放和侧滑。模式和布局修改用于下一次投放，先结束当前投放再重试；已保存的选择保留。

先解锁主屏启动投放，之后可锁定主屏继续使用背屏。结束时撤销临时保护并恢复原状态，不必为目标 App 修改电池设置；锁屏下无法启动新投放时，请先解锁。

具体操作、锁屏与停止行为和硬件要求见[虚拟背屏投放说明](virtual-rear-casting.md)。

### 截图与录屏

- **截图**：背屏显示目标画面后，点击截图磁贴。图片保存在 `Pictures/RearDisplay`，可在相册或文件管理中查看。
- **带壳截图**：在“背屏 → 背屏截图”开启“添加手机外壳”，选择完整机身或局部放大及机身配色；可同时保存原图。首次准备外壳需要联网，之后可离线使用。自动匹配小米 17 Pro / 17 Pro Max / 18 Pro / 18 Pro Max；17系列提供4种、18系列提供6种官方外观，配色列表随本机变化。其他机型仍可保存原始截图。外壳准备或合成失败时会保留原始截图并提示。截图磁贴和 `mrss://screenshot` 共用这些设置。
- **录屏**：点击录屏磁贴打开悬浮按钮。点击红色圆形开始，再点击方形停止；视频保存在 `Movies/ReMRSS_*.mp4`。悬浮窗可拖动，停止录制后可点击关闭按钮退出。

## 显示、充电与通知

- **DPI 与方向**：关闭虚拟投放时，“背屏显示”提供物理背屏 DPI 与四向旋转；虚拟模式下隐藏该组，通过“密度兼容”设置应用布局大小，通过背屏菜单旋转内容。显隐保留原值，遮盖、常亮、充电、截图和通知等共用功能继续显示。
- **常亮**：“背屏常亮”用于投放应用期间保持点亮，“持续唤醒”用于未投放应用时保持点亮，按需选择。
- **充电动画**：开启后接通电源显示绿色液体动画；需要充电期间持续显示时，再开启“充电动画常亮”。
- **背屏通知**：在“通知”页开启服务并选择来源应用，可设置隐藏标题/内容、跟随勿扰、仅倒扣时通知和自动销毁时间。允许本应用发送通知不能代替通知使用权。

## 权限与后台运行

“关于 → 权限检测”集中显示用途、状态和授权入口，从系统设置返回后自动刷新。按自己使用的功能授权即可。

| 权限或设置 | 使用场景 |
| --- | --- |
| Shizuku 或 Root（二选一） | 背屏切换、截图、录屏、显示控制及通知/充电动画 |
| 通知使用权 | 读取所选来源应用的通知并显示到背屏 |
| 通知发送 | 显示本应用的通知，Android 13 及以上需运行时授权 |
| 显示在其他应用上层 | 显示录屏悬浮控制按钮 |
| 应用列表访问 | 搜索和选择通知来源应用 |
| 安装未知应用 | 安装应用内下载的更新时使用 |

只手动使用磁贴时，通常无需锁定后台。长期使用通知、充电动画或常亮时，可检查后台运行、自启动与省电限制。ReMRSS 不显示在最近任务中，无需专门加锁。

“后台运行建议”检测的是 Android 电池优化豁免，小米应用省电的“无限制”是另一项设置。自启动和厂商省电策略无法可靠自动检测，应用会提示手动检查，并提供系统设置入口。

开启自启动不代表自动恢复全部功能。Shizuku 模式需要其服务已运行；Root 模式需要当前 root 环境与应用授权仍可用。临时 root 失效时需重新获取权限，应用不会自动改变权限来源。

## 自动化调用

在“关于 → 自动化入口”中查看或复制 URI，可用于 Tasker、MacroDroid 等自动化工具。

| 操作 | URI 示例 |
| --- | --- |
| 投放当前应用 | `mrss://switch?current=1` |
| 投放指定应用 | `mrss://switch?packageName=com.example.app` |
| 返回主屏 | `mrss://return?current=1` |
| 截图 | `mrss://screenshot` |
| 调整物理背屏显示 | `mrss://config?dpi=300&rotation=1` |

`rotation` 使用 `0` / `1` / `2` / `3`，分别对应 0° / 90° / 180° / 270°，并非直接传角度。

正式包为 `top.zainzh.rearscreen`；调试包为 `top.zainzh.rearscreen.debug`，调试协议为 `mrss-debug://`。若同时安装了其他处理 `mrss://` 的应用，请在自动化工具中指定 ReMRSS 目标包，避免命中旧版。

## 更新与排查

在“关于 → 检查更新”中手动检查。下载后应用会校验大小、SHA256、包名、版本和签名，再交给系统安装器确认；需要时再授予安装来源权限。

- **服务未连接**：检查首页所选权限来源。Shizuku 模式确认服务已运行并完成授权；Root 模式检查 root 管理器授权，再点击“授权并连接”。服务就绪后重新展开控制中心重试。
- **背屏已占用或投放内容消失**：先将原应用移回主屏，再重新投放。
- **通知未出现**：检查来源应用是否产生新通知、应用选择、通知使用权、勿扰/倒扣条件和后台限制。
- **充电动画未出现**：检查功能开关、当前权限来源的连接状态及后台限制。

仍有问题时，在“关于 → 诊断信息”查看连接状态，向 [Issues](https://github.com/lhly/MiRearScreenSwitcher/issues) 提供机型、系统版本、操作步骤和实际现象。

## Root 模式

Root 模式与 Shizuku 使用同一套背屏功能，不需要安装 Shizuku 或 Sui。首次申请由首页连接按钮发起；状态刷新和权限检测不会反复申请 root。连接失败后检查 root 管理器中的授权并主动重试，也可手动切回 Shizuku。

切换权限来源前，先将投放应用移回主屏、关闭录屏控制，并等待截图等操作完成。切换会重新连接控制服务，通知、充电和常亮按已保存的开关恢复；独立的通知使用权、悬浮窗等系统权限仍须正常授予。

正式版、调试版和独立 Root 测试版是不同安装包，root 授权不共享。独立验证构建使用 `top.zainzh.rearscreen.rootdebug`，仅用于与并行开发隔离，不是另一条发行分支。

诊断信息分别显示权限来源（Shizuku/Root）和实际服务 UID；Shizuku 自身以 root 启动时仍属于 Shizuku 模式。撤销 root 授权是否立即终止已运行的服务取决于 root 管理器，不能仅凭连接存活认定授权仍有效。
