# 应用布局与密度兼容

“密度兼容”入口位于“背屏 → 密度兼容”，初始及新 App 默认关闭。开启某个 App 后，投放会保留主屏渲染 DPI，并申请让应用接受虚拟屏指定的方向、宽高比和窗口尺寸。该策略仅作用于本会话创建的可信虚拟屏，不修改全局开发者选项。系统接口缺失、调用被拒绝或功能开关未启用时，继续使用原密度兼容并提示部分适配不可用。

搜索框下方提供“全部开启”和“全部关闭”文字按钮，单击即可作用于当前查询到的全部可投放应用，不受搜索筛选影响。批量操作只更新这些应用的密度兼容开关，不扫描或写入额外的每包默认键，也不修改已保存的布局 DPI；逐 App 开关仍可在批量操作后单独调整。未配置的新 App 仍默认为关闭。设置用于下一次虚拟投放，不改变当前会话。

已开启的 App 可设置 72–640 的布局 DPI。未设置数值或恢复默认时使用200，显式 URI `dpi` 参数优先，已保存的逐 App 数值保留。关闭兼容时暂不应用该 App 的布局 DPI，但保留保存值。修改用于下一次投放，当前会话保持原有方向和布局；下一次投放继续恢复该 App 已保存的旋转方向和显示范围。

设置页沿用 Compose/Miuix。数字编辑支持范围校验、草稿重建、恢复默认和键盘“完成”保存。横屏且键盘打开时收起重复说明，保留完整的数字输入区域。

默认摄像头避让现按最大可用空间投放：保留系统报告的cutout与不可用边界，取消圆角额外留白，不新增选项。已验手机区域由648×532扩大为680×596；下文调查阶段的旧区域数据用于说明变更原因。已有全域切换和逐App方向、范围、DPI偏好继续沿用。

### 视频显示面积复核

用户指出对比图中视频有效画面缩小，前述窗口、控件及旋转检查不足以验收视频观看效果。三张避让范围对比的物理输出区域均为 648×532；视频在开启适配且仍为 240 DPI 时已变小，200 DPI 未再明显缩小，不能单独归因为调低 DPI。

随后获用户同意，用同一条当前竖向视频进行主屏参考、兼容开关、DPI、方向策略和四向画面对照。诊断显式开启 `FLAG_RETRIEVE_INTERACTIVE_WINDOWS`、`FLAG_INCLUDE_NOT_IMPORTANT_VIEWS` 与资源 ID 获取，实际取得抖音窗口配置和 `SurfaceView` 节点可见边界；上一版仪器未启用交互窗口检索，因此此前列表为空不能证明系统不支持。

| 条件 | 播放器可见边界折算到物理背屏 | 应用配置 |
| --- | --- | --- |
| 关闭兼容，240 DPI | 436×532 | 291×355 dp，竖向配置 |
| 开启适配，240 DPI | 299×532 | 432×355 dp，横向配置 |
| 开启适配，200 DPI | 约299.2×532 | 518×426 dp，横向配置 |

开启后播放器保持约9∶16并使用整个可用高度。240 DPI 时虚拟播放器边界为 `[349,0][947,1064]`，经2倍缓冲缩放后为299×532；200 DPI 时为 `[418,0][1136,1277]`，折算后大小几乎相同。额外检查忽略应用方向请求的策略后，播放器边界保持不变，四向截图中的视频方向正常。

这些结果支持：应用窗口变为横向布局后，抖音改为按可用高度容纳竖向播放器；在所测视频中没有发现投放层对视频进行额外独立缩小的证据。436×532只是旧模式下可见、可能已被窗口裁切的边界，不将它误认为源视频分辨率或完整视频范围。要将9∶16画面加宽到648，需要1152高度，超出当前532高度，因而需要裁切或改变比例。

该轮据此保留现有等比显示，不加入自动裁切或抖音包名补丁；改动限于诊断和验收记录。该轮验证的是同一条当前竖向视频，未回到早先坦克对比视频；早先视频黑边是否编码在源视频内仍未直接确认。
