# 充电与通知首次显示稳定性修复验收（2026-10-16）

## 改动

针对[此前诊断](first-trigger-disappearance-diagnosis.md)确认的官方重启息屏回调，充电和通知不再调用 `disableSubScreenLauncher` 或杀死官方背屏进程。两者先唤醒背屏，再启动动画；不读写官方的重启息屏标记，也不修改系统息屏策略。

启动成功同时要求任务位于display1、任务确为背屏前台，避免把“窗口还存在但已被表盘盖住”当作成功。两类动画的前台变更操作在后台串行执行，每次有唯一会话代号。关闭、失败清理和恢复操作都核对会话，旧动画即使延迟结束，也不能结束新动画或在新动画之后恢复桌面。

通知启动及持续唤醒的Shell调用移到后台。连续通知通过 `onNewIntent` 更新会话并重建内容，取消旧定时器；通知正常结束复用统一的恢复接口，修正原来的 `com.xiaomi.mirror` 恢复目标，并保留恢复常亮充电的既有分支。通知内容使用Shell字面量转义。

App投放、磁贴、URI投放和投放保活服务的实现没有修改，本轮不覆盖其间歇性问题。

## 无线ADB真机验证

手机为小米2509FPN0BC，Android 17 / SDK37。通过已配对的无线ADB TLS连接同签名覆盖安装，原数据保留。

| 场景 | 验证 |
| --- | --- |
| 息屏后首次充电，2轮 | 开始前确认PowerGroup1为Dozing；1、3、6.5秒均为充电页前台，拔线后退出 |
| 息屏后首次通知，2轮 | 使用真实Shell通知→NotificationListener链路；1、3、6.5秒均为通知页前台，随后自然结束 |
| 连续通知 | 第二条通知持续跨过旧通知的关闭时刻，之后正常结束 |
| 充电→通知 | 通知取得前台后拔线，旧充电关闭和恢复不覆盖通知 |
| 通知→充电 | 充电持续跨过旧通知关闭时刻，拔线后正常结束 |

7组场景全部通过。官方 `com.xiaomi.subscreencenter` 进程从开始到结束保持PID12591，日志未再出现测试动作引发的 `SubScreenRestartDozeListener` 或官方重启息屏消息。

测试中的两次脚本断言已单独核对：一次把手动观察到的约8秒误当固定通知时长，改为有界等待自然结束后通过；另一次立即比较Awake与Dozing状态下的系统息屏标记，发现其会随系统状态变化，等待恢复同等Dozing状态后值仍为原来的1。没有通过修改该标记绕过问题。

本轮真机覆盖当前普通充电模式、连续通知及双向打断；完整常亮充电恢复和锁屏组合没有逐项新增真机验收，相关既有生命周期回归继续通过。
